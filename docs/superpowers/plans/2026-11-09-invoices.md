# Saved Invoices Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** List, open, change (atomic replace, incl. moving to another bike) and delete saved invoices.

**Architecture:** Server: one `undoInvoice(tx, doc)` that removes what a confirm created; `confirmInvoice` gains a `replace` path that runs undo + the normal save in one transaction; `deleteDocument` handles any status. UI: list on `/invoice`, Change/Delete on `/invoice/[docId]`, 🧾 links on Costs/History.

**Tech Stack:** Nuxt 4 SPA, Nitro, drizzle/Postgres, Vitest, Playwright (phone 380x780).

**Spec:** `docs/superpowers/specs/2026-11-09-invoices-design.md`

## Global Constraints
- Every query scoped by `userId`. Bad input 400, bad path id 404, never 500. New routes in `tests/e2e/bad-input.spec.ts`.
- UI uses `useApi()` only; Change/Delete are online-only (no `queue`).
- No browser dialogs; confirm is in-app.
- Money cents, `money()`; dates `date()`.
- Commit after each task with the session attribution lines.

## Review Focus
1. Replace that fails validation or totals (409) must leave the saved invoice exactly as it was (transaction rollback).
2. Replace onto another bike: item ids of the old bike must not leak; service meters checked against the new bike.
3. Undo touches only rows with this `documentId` and this `userId` (another invoice's movements on the same part stay).
4. Double-tap Change Save / Delete: second one must not double-undo (row lock on the document).
5. Delete of a part the invoice created only when every movement of that part is this invoice's.

- Test: `tests/unit/server/invoice-change.test.ts`, `tests/e2e/bad-input.spec.ts`

**Interfaces (produces):**
- `undoInvoice(tx: Tx, doc: Document): Promise<void>` — deletes `part_movements` (documentId, kind 'bought') lowering each part's qty by its qty; deletes `expenses` with documentId (expense_items cascade); deletes `services` with documentId (service_items cascade).
- `confirmInvoice(doc, bike, raw)` — when `raw.replace === true` and the locked doc is `confirmed`, runs `undoInvoice` first in the same transaction, then the normal save. `replace` on a non-confirmed doc = normal confirm. Without `replace`, confirmed stays 409.
- `deleteDocument(doc: Document): Promise<void>` — transaction, row lock; confirmed → `undoInvoice`, then delete parts whose every movement had this documentId (before undo) and that now have none; then delete the document (files cascade). Route `DELETE /api/documents/:id` → `{ ok: true }`. Keep `discard.delete.ts` calling it.
- `GET /api/documents` → `Array<{ id, status, supplierName, issuedAt, createdAt, totalCents, bikeId, bikeName, lines }>`, confirmed total = sum of its expenses; order: unconfirmed first, then `coalesce(issuedAt, createdAt)` desc.
- `GET /api/documents/:id` for confirmed adds `form: { bikeId, at, hoursTenths, km, garageName, lines: Array<{ description, amountCents, categoryId, itemIds, shelf: { partId, name, unit, qtyHundredths } | null }> }` and `stockWarnings: Array<{ name, unit, afterHundredths }>` (parts whose qty minus this invoice's bought qty < 0).
