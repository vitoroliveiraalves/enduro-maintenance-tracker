# Meters per Bike Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each bike counts hours & km, km only, or hours only, and every screen, API and status follows it, so the app works for street bikes.

**Architecture:** One bike column `meters` drives everything. A shared helper (`shared/utils/meters.ts`, auto-imported in app and server) answers "does this bike count hours / km". Reading meter columns become nullable; the server ignores uncounted values on every write (never a 400 for them) and status/costs read only counted units. Stored data is never rewritten on a switch.

**Tech Stack:** Nuxt 4 SPA, Nitro, Postgres 16, drizzle (`pnpm db:generate`), Vitest, Playwright (phone project 380x780).

**Spec:** `docs/superpowers/specs/2026-11-09-meters-design.md`

## Global Constraints

- `meters` values exactly `'hours_km' | 'km' | 'hours'`; default `'hours_km'`; labels exactly "Hours & km", "Km only", "Hours only"; the control's label "Counts".
- Uncounted values on writes: ignored (stored null / interval left unchanged), never a 400. Missing counted meter on a new reading or on bike create: 400.
- Services, mark-done and invoice-created services keep optional meters.
- Switching meters never rewrites stored rows. Status, costs and screens use the bike's *current* counted units only.
- Meters change on a bike is online-only (`mutate` without `queue`).
- Riding conditions (mud/sand/dust/race) only shown and only stored for bikes that count hours; otherwise a reading stores `'normal'`.
- Every `ORDER BY ... hours_tenths` tie-break puts NULLs last.
- CLAUDE.md rules all apply: `useApi()` only, `validate.ts`, bad-input spec for every new 400, `owned.ts`, English UI, dark tokens, 44 px targets, no browser dialogs, commit per task with the session attribution lines.

## Review Focus

1. An existing `hours_km` bike behaves exactly as before (status, costs, toasts, outbox text) — every task keeps the existing suites green unchanged except where a test asserts the new field.
2. A km-only bike never shows "h", "0.0 h" or an hours field anywhere (Task 6 e2e walks every screen and asserts no ` h` text in the bike's rows).
3. Switching `hours_km` → `km` → `hours_km` restores the hour-based status exactly (Task 2 test).
4. A queued offline reading for a km-only bike replays without hours (Task 5 e2e).
5. Readings with a null meter at the same timestamp as another reading sort deterministically (Task 1/2 tests use NULLS LAST).

### Task 2: Server writes and status follow the bike's meters

**Files:**
- Modify: `server/utils/bikes.ts` (parseBikeInput, createBike, cleanItem/intervals, defOf, itemRows, latestReading, listBikes, patchBike, createItem, patchItem, assertNotAboveMeters), `server/utils/readings.ts`, `server/utils/services.ts`, `server/utils/invoice-confirm.ts`, `server/utils/item-history.ts` (only if it orders by hours)
- Test: `tests/unit/server/bikes-api.test.ts`, `readings-api.test.ts`, `services-api.test.ts`, `invoice-confirm.test.ts`, `tests/e2e/bad-input.spec.ts`

**Interfaces — Consumes:** Task 1 helper. **Produces:** `parseReadingInput(raw, meters: BikeMeters)`; bike create body accepts `meters?: BikeMeters`; `PATCH /api/bikes/:id` accepts `meters`; `defOf(item, meters)`.

Rules (from the spec, exact):
- Bike create: `meters` optional (default `'hours_km'`), anything else → 400 `Invalid meters`. Counted current meters required (`int`), uncounted ignored → first reading stores null. Items: uncounted intervals become null; uncounted lastDone meters become null; then the existing "An item needs at least one interval" check runs (it may 400 — that is the existing rule, not an uncounted-value 400).
- Reading: counted meters required, uncounted stored null, `condition` stored `'normal'` when the bike doesn't count hours.
- Services / invoice confirm: `keepCounted` before `assertNotAboveMeters*` and insert; the "above meters" checks skip a meter that is null on either side.
- Item create: uncounted intervals → null. Item patch: uncounted interval keys in the body are ignored (stored value unchanged).
- Bike patch: `meters` validated with `isBikeMeters` → else 400 `Invalid meters`; no other effect (no rows rewritten).
- Status (`itemRows`) uses `countedDef(meters, defOf(item))`.
- All `orderBy(... hoursTenths)` tie-breaks: NULLS LAST (`sql\`${meterReadings.hoursTenths} desc nulls last\`` / `asc nulls last`).
